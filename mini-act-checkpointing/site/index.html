Activation checkpointing 的核心不是“保存 checkpoint 文件”，而是训练时少保存中间激活。 下面这个小实验会把普通 autograd、checkpoint forward、backward recompute 放在同一张图里。

02 / 从 autograd 开始

默认 autograd 为什么吃显存

backward 公式常常需要 forward 的输入或输出。比如 `sin(x)` 的反向要用 `x`， `linear(x, w)` 的反向要用 `x` 和 `w`。所以 eager autograd 会沿着 forward 一路保存张量， 峰值通常出现在 backward 开始之前。 

y = block(x)
loss = y.square().mean()
loss.backward()

普通 forward 会把 `block` 内部反向需要的激活挂在 graph 上。省事，但深模型会把激活堆到很高。

03 / checkpoint 的交换

只保存边界输入，把内部激活留到 backward 再造

checkpoint 区域的 forward 用 `torch.no_grad()` 包起来。内部算子照常产生结果， 但 autograd 不记录内部 graph，也就不会保存那些中间激活。代价是 backward 时要重跑一遍区域。 

with torch.no_grad():
    y = run_fn(x)       # 不保存内部激活

# backward:
with torch.enable_grad():
    y2 = run_fn(x_detached)
torch.autograd.backward(y2, grad_y)

反向里重算出的 `y2` 不是为了当输出，而是为了重新生成一个局部 graph，让 autograd 算梯度。

04 / 随机数不是小事

dropout mask 必须在重算时复现

如果 checkpoint forward 和 backward recompute 用了不同 dropout mask，同一个数学图就变成了两个图。 这就是 PyTorch 默认要 stash/restore RNG state 的原因。

05 / 实现拆解

一个教学版 checkpoint 需要四个零件

  1. 把 `args/kwargs` 里的 tensor leaf 摘出来，非 tensor 常量留在 tree spec 里。
  2. forward 保存 tensor inputs 与 RNG，然后 `no_grad` 跑 function。
  3. backward 里 detach inputs，按原 tree spec 还原调用参数。
  4. 恢复 RNG、重跑 function、把外部传来的 `grad_outputs` 接给重算 outputs。

06 / PyTorch 生产版桥段

non-reentrant 用 hooks，不是简单 backward 重跑全部

PyTorch 当前推荐 `use_reentrant=False`。它的关键是 saved tensor hooks： forward 仍然记录 graph，但把本该保存的大 tensor 换成 holder；等 backward 真要解包某个 tensor， holder 才触发 recompute。拿到足够 tensor 后可以 early stop。

07 / 代码判读

读 checkpoint 代码时，先判断这句在保护什么

with torch.no_grad():
    outputs = run_fn(*args)

判断：这是为了不保存 checkpoint 区域内部激活？

saved_inputs = ctx.saved_tensors
detached = x.detach().requires_grad_(True)

判断：detach 会切断最终输入梯度，所以不能用？

torch.autograd.backward(
    recomputed_outputs,
    grad_outputs,
)

判断：这里是在重算出来的局部 graph 上求输入和参数梯度？

08 / 取舍地图

省显存不是免费午餐

checkpoint 的收益取决于“激活有多大”和“重算有多贵”。Transformer block 这类深而规整的区域很适合； 如果区域里有副作用、全局状态变化、随机数未回放、或者重算比保存还贵，就要小心。
