# Jev / TETRIS

一个可手动玩、也可交给 Jev 的俄罗斯方块实验。浏览器预览当前配置生成的**纯文本 state**；Node 服务端根据棋盘快照与同一配置重新编码、计算候选，然后通过官方 `@typesafe-ai/sdk` 提问“下一步执行什么动作”，将 `Choice` 的选择原样交给同一个游戏引擎执行。服务端拒绝候选之外的返回动作。

## 启动

需要 Node.js 22.9+。密钥保存在 `~/.env` 或本目录 `.env`：

```dotenv
TYPESAFE_API_KEY=你的密钥
TYPESAFE_DEFAULT_MODEL=jev-latest
```

```sh
cd /Users/siancao/work/ai/research/jev-tetris
npm ci
npm start
```

打开 http://127.0.0.1:4173 。`npm start` 先读 `~/.env`，再读本目录 `.env`，后者覆盖前者。已存在的进程环境变量优先。密钥不发送给浏览器，也不写入实验记录。默认只监听本机，并只接受 localhost / 127.0.0.1 / ::1 的 Host；本次未发布到公网。

## 使用

- **Jev 下一步**：冻结当前棋盘，调用一次模型，再执行一个动作。
- **连续运行**：每次使用最新状态，上限默认 50 次，可设 1–500 次；停止后，未返回的动作丢弃。请求失败、游戏结束、模型暂停或重开时停止。
- **手动操作**：按钮与键盘均可，随时操作会停止自动运行并使未返回的模型决策失效。手动与模型共享引擎和全部动作。
- **自动时钟**：手动模式每 150ms 产生一个 wait；默认关闭。Jev 接手时关闭，网络时间不影响棋盘。
- **STATE**：当前棋盘，即下一次调用的 state。**决策记录**中可展开已完成请求，查看当时的输入、提问、模型、概率、耗时、执行后状态。
- **模型与提问**：可修改模型 ID 和问题，便于比较提示词效果。
- **导出记录**：下载完整 JSON。记录只保留在当前页面内存中，刷新前请导出；页面最多渲染最近 100 条，但导出包含全部记录。

| 操作 | 键盘 | Jev action |
|---|---|---|
| 左 / 右 | ← / →，A / D | left / right |
| 软降 / 硬降 | ↓ 或 S / Space | soft_drop / hard_drop |
| 顺时针 / 逆时针 | ↑、W、X / Z | rotate_cw / rotate_ccw |
| 180° | Q | rotate_180 |
| 暂存 / 交换 | C | hold |
| 等待一拍 | . | wait |
| 暂停 / 继续 | P | pause / resume |
| 同种子重开 | R | restart |

按住左右或软降键可连续移动；其他动作不接受系统按键重复。默认仅将当前合法动作传给 Jev；可切换为全部 12 个动作基线。手动操作不受筛选限制，撞墙或不可用的暂存仍消耗一拍。

## 实验规则与边界

10×20 棋盘、种子七袋随机、五个预览、暂存每块一次、90° SRS 踢墙；180° 定义为同一拍两次独立顺时针尝试，可能只转成 90°。固定每 5 拍重力下降一格，触地 2 拍锁定，移动/旋转最多重置 15 次。硬降立即锁定。四种消行得分为 100/300/500/800，软降和硬降本身不加分，只有消行加分；没有等级加速、T-spin 或连击奖励。这是明确规则的离散动作实验，不声称完整复刻某一商业 Tetris 版本。

文本包括坐标图、大小写区分活动与锁定方块、活动坐标和朝向、当前投影落点、预览队列、暂存、分数、计时、最近 8 步和规则。投影仅是人类也能看到的当前落点；代码不搜索更好的落点、不排序候选、不替换模型动作。随机生成器内部状态和未显示的后续方块不发给模型。

同一种子与相同动作序列会重现游戏状态；Jev 的未来响应不保证相同。Jev 返回动作分布和置信度，**不返回思维链**；置信度不是正确率。默认英文问题符合其主要训练语言，页面为中文。

## 可配置输入实验

“输入实验配置”中三个维度独立切换，选择会保存在当前浏览器。原始完整文本 + 全部动作 + 不附加指标 + 全部段落开启，保留完整信息；当前版本将消行字段明确命名为 cleared_lines。历史记录保持原样。

| 配置 | 选项 | 实际影响 |
|---|---|---|
| State 编码 | 原始完整文本 / 精简棋盘文本 / 方块坐标列表 / JSON 文本 | 改变棋盘表示；规则、队列、暂存、计时、活动方块、投影和历史信息保持一致 |
| 动作候选 | 仅当前合法动作（默认） / 全部 12 个动作 | 同时改变 state 内的候选说明与 SDK Choice.criteria；不是仅在提示词中要求合法 |
| 附加指标 | 开 / 关（默认） | 追加列高、最高列、空洞数、表面起伏及定义，仅计算已锁定方块 |

精简棋盘去掉逐行坐标前缀；坐标模式只列出占用单元格；JSON 仍以**字符串**发送，不改变成对象输入。JSON 的 `board` 为行数组，`context` 保留公共说明，`available_actions` 为当前候选。指标不评价任何候选动作，也不预测或搜索后续落点。

合法动作在输入生效前计算，排除撞墙/碰撞、无法下降、无法旋转、O 方块无效旋转、用过的暂存等。必须考虑 SRS 踢墙，不能把“操作无效但重力导致棋盘变化”当作合法。触地硬降仍合法，因为会立即锁定；等待、暂停和重开保留。暂停时只有继续/重开，结束时只有重开。可能导致失败的合法动作仍保留。

勾选**仅观察选择，不执行动作**，然后在同一个棋盘切换上述配置，逐次点“Jev 下一步”。连续运行在该模式下禁用。改变任一配置会停止连续运行和自动时钟，使尚未返回的决策失效，保留棋盘。取消勾选后恢复实际执行。

每条记录包含当时的 `config`、实际发送的 `state` 和 `actions`、`gameBefore`/`gameAfter` 快照、`executed` 标记、模型/概率/耗时；过期响应另标记 `discarded`。导出升级为 `jev-tetris-v2`，顶层配置只是导出时配置，各条记录的配置才是该次请求依据。旧的 `live-run.json` 不改写。

`live-config-run.json` 保存新增功能的真实浏览器验证：seed=42 的 T 方块左移到墙边，固定在 BEAT 3，四种编码（合法动作）、JSON 加指标、原始文本全动作，共六次仅观察。前五次候选均为 10 个，排除 left/resume；基线为 12 个。每次返回的 state 均与页面预览逐字相同，棋盘均未推进。该样本六次仍全部选择 hard_drop；它是接入和对比方法的验证，不是编码效果的统计结论。

## 排除动作

在“输入实验配置 → 排除动作”勾选不希望 Jev 使用的动作，例如 `hard_drop`。最终候选 = 全部动作（或合法动作）减去 `excludedActions`，四种 state 与 SDK criteria 同时生效。默认排除列表为空；设置会保存在浏览器、写入每条实验记录及导出配置。该选项仅限制 Jev，不影响手动按键。候选为空时停止请求，不会自动恢复被排除动作。

本次实机验证：排除 hard_drop 后，真实 Jev 返回并执行 soft_drop；全部排除时按钮禁用；刷新后保留 hard_drop 排除设置。相关配置/服务端测试通过。全量回归 24/25 通过，历史 state 精确回放因当前目标文案新增 “as long as possible” 与旧 live-run.json 不同而失败；未改写历史记录或覆盖当前目标文案。


## 按段落调整 state

“State 段落（勾选保留）”提供独立开关：目标、活动方块、落点投影、预览/暂存、得分与消行、运行状态、计时、Rules、形状说明、Recent actions、动作说明。棋盘、坐标和符号解释始终保留。关闭 Rules 会移除重力、锁定、七袋、碰撞与计分规则段；形状矩阵和最近动作有各自开关。动作的 SDK 候选描述仍然存在，关闭“动作说明”只去掉 state 中重复的说明，不会改变候选集合。

得分段使用 `score=...; cleared_lines=...; locked_pieces=...`，当前拍数、暂停/结束和随机种子单列为运行状态，方便只保留要观察的信息。段落选择在所有四种编码中生效，实时更新预览；配置持久化到浏览器，并随每次请求和导出保存在 `config.sections`。旧浏览器配置缺少 sections 时默认全部开启。

例如关闭 Recent actions 和 Rules：

```json
{"sections":{"history":false,"rules":false}}
```

改变开关会停止连续运行并丢弃尚未返回的旧决策，棋盘保持不变。历史真实记录不改写；旧记录的回放检查验证棋盘、方块和计数等实际游戏状态，不要求历史目标文案与新版逐字一致。

本次段落功能验证：28/28 测试通过；历史回放已按实际游戏字段核对，之前的文案差异失败已解决，历史文件未改写。浏览器实测关闭 Rules/Recent actions 后，原始文本由 3042 降至 1865 字符，真实 original/JSON 请求与预览一致，刷新后开关保留。

## JSON 对象（分段字段）

新增第五种编码 `json_object`。它将每个启用的段落作为独立字段，直接把字典对象作为 SDK `state` 传入，不先转换成 JSON 字符串。例如 `goal`、`board`、`active`、`stats`、`rules`、`history`。字段值保留对应段落的原始文本，避免同时改变信息内容；启用的 `metrics` 仍为结构化指标对象。关闭段落会删除整个字段，`board` 始终存在。旧的 `json` 模式仍是 JSON 文本字符串。

页面把对象格式化显示与复制；请求、响应、逐步日志和导出的 state 保持对象类型。已验证真实 Jev 接收对象、返回有效动作，且对象内容与预览一致。SDK 序列化测试直接核对 HTTP 请求里的 state 是对象，非二次编码的字符串。当前 30/30 测试通过。

## Choice 执行后状态

“Choice 内容”新增 `执行后状态（单步模拟）`，配置为 `choiceMode: "outcome"`。默认 `description` 保留原动作描述。新模式实际传给 SDK 的 `criteria` 为 `{"left": {...}, "right": {...}}`，每个候选用 `structuredClone(game)` 再执行同一个 `step()` 得出，不推进真实棋盘、不排序或筛选优劣。

每个对象包含：

- `score_after`、`score_delta`：执行后总分和本次变化。
- `cleared_lines_after`、`newly_cleared_lines`：累计消行和本次新增消行。
- `active_after`：执行后活动方块的 type/x/y/rotation 和实际格子坐标；`spawned_new_piece` 指明本次是否生成或换入了新活动块。
- `next_piece_type`：执行后预览队列中的第一块类型。它尚未生成，不应把它与 `active_after` 混淆。
- 暂存、是否可暂存、拍数、重力/锁定计时、暂停与结束状态。
- `reset_run`：重开标记。重开会将分数和累计消行归零，`score_delta`、`locked_pieces_delta` 因此可能为负；`newly_cleared_lines` 不为负。

只模拟一次动作和本拍自动重力/锁定，不模拟后续动作，也不暴露内部 RNG、bag 或未显示的长队列。普通左移后的结果不等于“左移然后硬降”的最终落点。若本拍锁定并消行，`active_after` 就是新生成方块的位置。

此配置独立于五种 state 编码、合法动作、排除动作和段落开关。关闭 state 的动作说明仍会把对象型 criteria 传给 SDK。页面“查看实际 Choice 输入”可直接核对对象；日志、导出和浏览器持久化均保留该模式及真实候选。JSON 对象 state 的 actions 字段在此模式下也使用对象。

验证：33/33 测试通过；真实 Jev 选择 soft_drop 后的分数与方块位置和模拟一致，刷新后模式及原有排除设置保留。


## 当前评分与增强 Choice（仅消行得分）

当前计分只保留消行奖励：一次消除 1/2/3/4 行分别 100/300/500/800 分。软降、硬降和其他移动本身都是 0 分；硬降如果同时消行，仍获得对应消行分。此前记录中的下落奖励和旧实测分数仅属于历史版本，不改写旧 JSON。

`执行后变化与收益` 仍返回一个原始动作。每个候选除已有位置/消行字段外增加：

- `benefit`：本拍实际消行和得分、方块是否锁定、空洞变化的文字描述。
- `board_after`：执行动作后的锁定棋盘列高、最高高度、空洞、起伏，以及相对动作前的变化。
- `landing_preview`：若当前块尚未锁定，另模拟从动作后位置立即硬降的条件结果，包括落点格子、额外消行/分数和棋盘质量；明确标记 `requires_additional_hard_drop: true`，该硬降**不会执行**。动作已经锁定时不再预测下一块，只标记已落定；暂停、继续和重开不提供该预览。

这没有枚举所有落点、没有替 Jev 排序，也不改变每次只执行一个动作。`left` 的即时得分可以为 0，但其 `landing_preview` 可以显示再硬降能消两行、得 300 分；直接 hard_drop 则可以显示 0 分、新增空洞。旧 `horizon` 仅描述实际一步，preview 用独立字段描述另一个有条件的未来。

导出升级为 `jev-tetris-v3`，每条新记录标记 `scoring: "line-clears-only-v1"`，避免与旧下落加分版本混淆。新评分从重新加载后的新对局开始；打开旧页面的用户需刷新。

本版验证：35/35 测试通过。浏览器软降后 score=0，随后硬降落下 1 块、消行 0，score 仍为 0。一次真实 Jev 1.13.0 两行缺口请求中保留 hard_drop，模型选择 left（0.43），hard_drop 为 0.35；这是单次结果，不代表稳定胜率。请求使用 json_object / outcome，隐藏 state 中重复的 actions、history、rules 段，但保留完整 SDK criteria。已在交付页面恢复 hard_drop 候选。

## 额外前瞻 0 / 1 / 2 步

`lookaheadDepth` 为 0、1、2，默认 0 保留原有行为。仅在 Choice 后果模式生效。步数指选中的首动作之后，额外执行的移动/软降/旋转次数，不含首动作和最后的条件硬降预览。

每个首动作独立枚举最多两步合法后续操作，遵守动作排除设置。逐步使用真实引擎的重力和锁定规则；本块锁定或结束后不再搜索下一块。后续不包含暂存、等待、暂停、继续或重开。第一步若是暂存，则可以分析换入的方块。

为控制输入长度，每个首动作只提供一条最佳后续预览：先避免结束，再比较更多消行、更少空洞、更低高度、更平整表面，最后优先更短路径。这个排序仅用于生成每个首动作的前瞻摘要，不替 Jev 选择或删除首动作。`lookahead_preview` 显示后续路径、额外收益、最终棋盘指标和假设；游戏只执行首动作，下一次请求会基于实际棋盘重新计算。

末尾硬降仍是条件预览，若 hard_drop 被排除，会明确说明该假设动作不在允许候选中。0 步时只有原 `landing_preview`；暂停、继续、重开或已锁定/结束的首动作不会前瞻下一块。

本版验证：38/38 检查通过。真实开局调用（seed 42、2 步、hard_drop 未排除）返回 left，实际仅 tick 0→1、锁定块数保持 0；后续预览未执行。刷新后 2 步配置保留，导出中记录 lookaheadDepth 和完整前瞻结果。

## 同一行横移＋旋转落点评估

新增 `choiceMode: "row_placements"`，可在“Choice 内容”中选择；原有描述模式、一步收益和 0/1/2 步前瞻保留。

以当前活动块的所在行为基准，逐格检查左右通路，枚举可达的横移距离。Choice 包括 left/right、left_2/right_2 等多格横移、合法的原地旋转、hard_drop。每个横移动作的 `variants` 列出保持朝向以及允许旋转后的独特落地结果，包含落点格子、落定消行后的 20 行棋盘、得分变化、新增消行、空洞、最高高度和起伏。`best_variant_index` 只是按存活、消行、空洞、高度和平整度标出该动作中较好的一个方案，所有方案均保留给 Jev。

实际仅执行 `execute_now`。例如 left_2 逐格验证两格路径，整条路径可达才横移两格；不旋转、不额外硬降，然后正常推进一拍（含本拍重力和锁定）。若首步已锁定或结束，候选只提供实际首步结果，不再计算旧块的后续旋转。否则落点评估是冻结当前行的几何预览，旋转沿用 SRS；实际重力可能改变下一次决策的位置，届时会重新计算。

模式始终只提供可达动作，不受“全部12动作”开关影响，也不使用额外前瞻步数。运行中不提供 hold/wait/pause/restart；暂停和结束时提供相应恢复控制。排除 left/right 会同时排除该方向所有多格移动，也可单独排除 left_2 等动作。排除 hard_drop 会移除该执行候选，但仍保留明确标注的假设直落收益。

验证：51/51 测试通过。空棋盘 L（x=3,y=0,rotation=0）产生 11 个当前动作、32 个独特落地变体。真实默认提问调用跑通；单独的执行诊断明确要求 left_2，验证实际 x 减少2、y/旋转/锁定块数不变、tick只加1，旋转和硬降预览未执行。配置刷新后保留，日志和导出包含实际宏动作与全部预览；诊断强制指令只用于验证执行路径，不代表自然选择能力提升。

## 精简 Choice 收益摘要（当前输出）

后果/前瞻/同一行落点评估的计算与动作集合不变，但实际发给 Jev 的每个 Choice 值现在只有三个字段：

- `immediate_gain`：只执行当前动作后的得分变化、新增消行、是否结束。
- `expected_gain`：完成下方条件路径后的总得分变化、新增消行、空洞变化、最高高度变化、最终表面起伏及是否结束。变化量均相对决策前的棋盘；消行是新增数量，不是累计行数。
- `followup`：达到预期收益还需执行的动作。空数组表示无需后续动作；这些动作不会自动执行。

同一行模式使用原 best_variant_index 所对应的收益，不再发送所有旋转变体。完整棋盘、格子坐标、方块姿态、计时及重复解释均留在内部模拟，不进入 Choice，也不进入 state 中重复的 actions 段。state 的独立棋盘段仍按原设计保留。描述模式仍为原来的短字符串。

验证：52/52 测试通过；原 seed42 开局同一行候选 JSON 从 33113 字符缩为 2424 字符（约减少93%）。真实 Jev 返回 left_3，记录中候选与页面摘要一致。该调用仅观察，没有改变对局。

## 问题与状态职责、收益文字说明（当前输出）

默认问题仅为 `Which action should the player take next?`。目标、规则、偏好和字段解释移至 state 的 `decision_guide`，对应“决策与收益说明”独立开关，默认开启。五种编码均适用。关闭该段表示明确移除这些说明，问题中不会偷偷补回。

实际 Choice 现在只有 `immediate_gain` 与 `expected_gain`，原数值保留，每组增加 `summary` 短句。即时说明直接描述本拍新增消行、积分变化和是否结束；预期说明明确是否有条件，并把空洞增减、堆叠升降和平整程度写成文字。数值指标和模拟算法不变。

state 明确说明：score 为积分变化，cleared_lines 为新增行数；expected_gain 相对决策前计算，已包含即时收益，不能与 immediate_gain 相加。预期收益不是保证，不会自动执行后续计划。holes_delta 负值是减少空洞，正值是增加，零只是数量不变而非没有空洞；height_delta 负值为降低堆叠；surface_roughness 是最终相邻列高度差总和，越小越平，采用 0–4 平坦、5–9 稍不平、10–16 凹凸、17+ 非常崎岖的文字等级。game_over 明确指示失败结果。

公开 Choice、SDK criteria、页面摘要和导出的实际候选均不再含 followup；内部模拟仍保留必要路径以核对条件收益，不把路径作为下一次决策的计划。保持每次只执行选中的动作。

验证：54/54 检查通过，真实请求核对了短问题、state 说明存在、两类收益及无 followup。模型此次返回 left_3（仅观察）。


## 修正：保留所有旋转的预期收益（当前 schema）

前一版精简曾读取 `best_variant_index`，只输出一个 expected_gain；这丢失了同一横移动作下其他旋转的收益。现已删除同一行评估中的最佳变体筛选，输出改为 `expected_gains` 数组，按原枚举顺序保留全部不同的可行落地结果。候选集合、实际执行动作和收益数值计算不变。

例如 right_2 的数组可包含：不旋转后硬降、顺时针后硬降、逆时针后硬降、180度后硬降。每项只有 scenario、收益数字和短说明，没有棋盘、格子坐标或 followup 执行列表。相同最终落地状态去重；被排除或不可行的旋转不出现。首步已锁定则只保留实际结果。旧的一步/有界前瞻模式仍使用各自原来的预览方法，以单元素数组保持格式一致。

state 的 decision_guide 明确：数组是互斥的可能结果，不是连续执行步骤，不能求和或与 immediate_gain 重复相加；不应把好坏旋转平均掉，而要比较当前动作是否提供有价值且可行的机会。减少空洞、降低高度、改善平整度也是收益，即使 score 和 cleared_lines 为0。存在好结果不代表会自动实现，下一次决策仍从实际棋盘重新选择。

验证：57/57 检查通过，包括 L 的 right_2 全部旋转收益逐项相等，以及零得分、零消行但减少4个空洞的方案被保留。历史 JSON 不改写。

## Reachable placements：当前块可达落点搜索

在 Choice 内容选择 `可达落点搜索（最多20项）`。它与同一行几何预览不同：使用真实 `step` 逐步搜索横移、软降、旋转、硬降、等待与多格宏动作，包含重力/锁定计时，因此可以找到先下降再侧移、低位旋转的路径。搜索到当前块首次锁定或游戏结束即停止，不搜索下一块；hold、pause、resume、restart 不属于搜索边。

默认 `search: {maxStates:5000,maxPathLength:64,maxChoices:20}`。页面可调：状态 1–10000、路径 1–128（包含最后锁定动作）、候选 1–20。20 项只限制最终展示，不在 BFS 中按收益剪成20个节点。每个搜索节点保存前驱，不复制整条路径；去重包含位置、朝向、重力阶段、触地计时、重置次数和必要计分状态，排除绝对 tick/history。被阻挡的输入仍按引擎规则消耗一拍，允许作为状态转移；所有禁用动作及禁用方向的宏动作均不会使用。

终态按棋盘、消行、得分、结束状态及后继相关引擎状态去重，保留最短路径。每个不同终态都从原始快照逐条回放，确认最后一步恰为首次锁定/结束且终态一致。已验证目标也可通过剩余路径重新回放加入。只有验证通过的方案可以送给 Jev。

筛选先优先生存方案，再保留有效当前目标及消行最多、空洞最少、高度最低、表面最平的代表方案，随后按 `100*clearedLines -40*holesDelta -4*heightDelta -roughnessDelta` 补齐。最后按该分降序、路径长度升序、稳定ID排序；低于5个名额时优先保留目标，再依次填代表。这是公开记录的候选筛选启发式，不是 Jev 置信度。

每个公开 Choice 是独立落点 ID，只包含 `execute_now`、简短收益 `summary`（空洞/高度/起伏的前后值）、`steps_to_lock`、`is_current_target`。完整路径、棋盘和排序分仅在应用内部及导出记录中，不传给模型。默认问题是 `Which placement should the player choose?`；用途与规则在 state 的决策说明中。

服务端把所选落点ID映射到已验证路径；客户端验证状态版本后只执行首动作，保存剩余路径。下一次仍让 Jev 选择，旧目标有效时保留名额并标记，收益近似时提示继续。锁定、手动操作、修改配置/问题/模型会清理目标；停止连续运行本身不移动棋盘。目标选择变化会计入切换次数。不会自动执行整个计划。

页面和日志显示 visited_states、unique_outcomes、verified_outcomes、shown_choices、search_complete、truncated_by、搜索/回放耗时以及目标切换次数。碰到预算后仍返回已验证结果并标记不完整，不能称为完整可达集合。开局 T 默认预算实测搜索5000状态、34个不同终态、展示20项，因 maxStates 截断；一次本机搜索约0.7秒，仅为诊断值。前端缓存同一棋盘/配置/目标的计算结果以避免重复渲染重复搜索。

导出 `jev-tetris-v4` 包含 choice_id、execute_now、state_version、selected_plan、remaining_plan、placement_details、search 与 target_switches；旧模式保持原动作语义。新增模块为 `placement-search.js`（搜索/去重/筛选）和 `placement-plan.js`（回放/身份/单步执行），没有增加依赖。

本版验收：72/72 自动检查通过。真实 Jev 三轮选择同一目标，执行 rotate_180 → left_3 → hard_drop；每次 tick 只加1，剩余路径3→2→1→0，锁定后目标清空、切换次数0，最终状态与首次回放终态逐字段一致。完整导出保存在 `live-reachable-run.json`。该记录证明接口和执行链路有效，不代表整体游戏策略最优。
