HRM-Text：不是把模型做大，而是让每个 token 更有用

这篇论文的核心主张很锋利：如果架构、目标函数和数据形态一起设计，1B 参数模型也可以用很小的训练预算进入 2B-7B open model 的性能区间。

1BHRM-Text 参数规模
40Bunique tokens 训练数据
$1.5k约 46 小时，16 张 H100

One Sentence

一句话读懂

HRM-Text 把语言模型看成一个“先理解任务、再反复执行”的系统：慢速的 H module 保持高层语义状态，快速的 L module 做局部迭代；训练时只对 response 计 loss，并用 PrefixLM 让 instruction 内部可以双向互看。

它反对什么？

反对把“从头预训练”默认等同于 trillion tokens、大集群、raw-text next-token prediction。作者想证明：小预算也能做 architecture-level pretraining research。

它押注什么？

押注结构先验：让模型有更多“内部计算步”，但不等价增加参数；同时把训练目标贴近真实使用场景，即给定 instruction 生成 answer。

它不能证明什么？

它不是“1B 全面打败 7B”的证明。它更像 existence proof：在 instruction-heavy 数据和小预算下，co-design 能显著改变 compute-to-performance ratio。

读法提醒：论文中同时出现 40B unique tokens 和 60B training duration tokens。前者是去重数据规模，后者是带重复采样的训练 token 数；效率图强调 40B unique tokens。

Glossary First

先把术语放稳

这篇论文的术语很多，但主线其实不复杂：它在 Transformer block 外面加了“循环计算”，再用训练技巧避免循环带来的梯度问题。

H module

High-level / slow state。它每个大周期更新一次，更像“当前任务语义、计划、全局上下文”的状态容器。

L module

Low-level / fast state。它在一次 H 更新前连续执行 3 次，用来做局部 refinement。

MagicNorm

内部用 PreNorm 保留梯度通路，模块出口再加一个 norm 控制 forward variance。关键在 N 个 forward steps 与 K 个 backward steps 的不对称。

Warmup deep credit

不是一开始就让梯度穿过很长循环链。训练初期 K=2，之后线性 warm up 到 K=5。

Task-completion objective

不对 instruction token 计 loss，只优化 -log P(xa | xq)。也就是把学习压力集中在“回答得对”。

PrefixLM mask

Instruction segment 内部双向 attention；response segment 仍然 causal。这样 decoder-only 实现里有一点 encoder-decoder 的味道。

Architecture

HRM-Text 的计算流

论文里的 forward pass 是两个高层周期；每个周期先做三次快速 L 更新，再做一次慢速 H 更新。你可以把它看成：同一组参数被重复调用，让模型获得更深的 serial computation。

双时间尺度 recurrence

Canvas 图按论文设定画出 H2L3：2 个 H cycles，每个 cycle 包含 3 个 L updates 和 1 个 H update。

输入 embedding 初始化 H state 和 L state。每个 H cycle 中 L module 连续更新三次，然后 H module 更新一次，最终 H state 进入 LM head 产生 logits。

# H2L3: two high-level cycles, three low-level steps per cycle
z_H = init_from_input_embeddings(tokens)
z_L = fixed_low_level_state()

for h_cycle in range(2):
    for l_step in range(3):
        z_L = L_module(z_L, z_H, mask)

    z_H = H_module(z_H, z_L, mask)

logits = lm_head(z_H)

PreNorm 梯度路径干净，但 residual 累加可能让 hidden-state variance 长大。
PostNorm forward activation 更稳，但 normalization 可能切断干净的 identity gradient path。
MagicNorm 内部 PreNorm，出口 Norm；用 TBPTT 的短 backward horizon 避开纯 PostNorm 的训练痛点。

Objective

训练目标为什么重要

作者认为 raw-text next-token prediction 在小预算下浪费了很多学习信号：真实推理时，prompt 已经给定；模型真正需要学的是如何根据 prompt 产出 response。

PrefixLM attention mask

绿色区域是 instruction token 之间的双向 attention；珊瑚色区域是 response token 的 causal generation。

普通 causal LM：-log P(x) 把 instruction 和 response 都当作要预测的 token。对已知 prompt 也交 loss。
Task-completion：-log P(xa | xq) 只在 answer 上计 loss，让小预算训练更专注于完成任务。
PrefixLM：prompt 先被充分整合 Instruction 内 token 可以互相看，response 仍按自回归方式生成。 
# tokens = [instruction prefix | response suffix]
loss_mask = response_positions_only

attention(i, j) =
    allow if i and j are both in instruction
    allow if i is response and j <= i
    block otherwise

What To Believe

结论应该怎么拿捏

这篇论文最值得记住的不是“一个新模型名”，而是一个设计原则：当模型预算很小，架构、目标函数、数据格式之间的错配会被放大；反过来，co-design 的收益也会变大。

1
HRM 的价值：把深度变成时间 重复调用 H/L modules 相当于给模型更多内部计算步，而不是简单堆更多独立参数。
2
MagicNorm 的价值：让循环不要炸 递归模型的难点是长链反传。MagicNorm 和 warmup horizon 都是在控制这个优化风险。
3
PrefixLM 的价值：别让 prompt 浪费 loss Instruction 已知，response 才是要完成的任务；这让训练目标更贴近 inference。
可信之处 作者给了 FLOPs-matched comparison、objective ablation、dataset contamination test 和 effective depth analysis，证据链不只靠最终榜单。
谨慎之处 这是 arXiv v1 preprint；baseline 数字混合了原论文报告和重新评测，且只展示到 HRM-Text 1B 规模。
工程代价 固定 recurrence 会增加 inference 计算；PrefixLM 的 multi-turn KV cache 逻辑也需要 serving 框架显式处理。
