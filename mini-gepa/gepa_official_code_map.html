算法心跳

论文设计的四个落点

自然语言反思不是奖励标量的替代品，而是学习介质。

论文强调从 reasoning、tool calls、tool outputs 等轨迹中诊断失败原因。代码中这落在 adapter 的 trace 捕获和 reflective dataset 构造。

Pareto 前沿不是一个分数榜，而是一组“局部擅长者”。

官方实现按验证样本、目标或二者组合维护 frontier，使某些候选即使平均分不最高，也能成为父代。

变异先在 minibatch 上试探，再进入全验证更新。

反思 proposer 先比较 parent 与 child 的 minibatch 分数；通过 acceptance 后，engine 才把候选加入池并更新 Pareto 状态。

合并不是平均两个 prompt，而是沿共同祖先做结构化拼接。

官方 merge proposer 会寻找共享祖先的 Pareto 候选对，逐组件判断互补改动，再用验证子集决定是否值得全量评估。

Candidate命名文本组件的映射，如 system prompt、agent policy、代码片段。
Trajectory执行过程证据。GEPA 核心不解释它，由 adapter 转成反思数据。
ASIActionable Side Information，页面中对应 reflective dataset。
Merge把两个 Pareto 候选相对共同祖先的互补改动拼成新候选。
1. 公开入口 2. Adapter 合同 3. 优化循环 4. 反思变异 5. Pareto 状态 6. 系统感知合并

一眼读懂：官方实现与教学版的差异

教学版：一个 prompt。

官方版：`dict[str, str]` 多组件 candidate，并通过 component selector 决定本轮修改哪个组件。

教学版：规则化反思。

官方版：adapter 产出 reflective dataset，默认通过 reflection LM 生成新文本，同时保留 prompt 与 raw output 元数据。

教学版：简单 Pareto。

官方版：支持 instance/objective/hybrid/cartesian frontier，还能用 merge 把互补候选重新组合。
